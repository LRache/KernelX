# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
make menuconfig      # Configure build (arch, cross-compiler, QEMU paths, features)
make check           # Fast compile check (no linking)
make build           # Full build → build/<ARCH><ARCH_BITS>/vmkernelx
make run             # Build and run in QEMU
make gdb             # Build and run in QEMU waiting for GDB
make clean           # Remove all build artifacts
make objdump         # Disassemble kernel to kernel.asm
```

Build is configured via `config/.config` (generated by `make menuconfig`). Key variables:
- `ARCH` / `ARCH_BITS` — target architecture (e.g. `riscv` / `64`)
- `CROSS_COMPILE` — toolchain prefix (e.g. `riscv64-unknown-elf-`)
- `COMPILE_MODE` — `debug` (default) or `release`
- `LOG_LEVEL` — `trace`, `debug`, `info`, `warn`

Cargo features (set via Kconfig / build.mk): `swap-memory`, `log-trace-syscall`, `warn-unimplemented-syscall`, `deadlock-detect`, `no-smp`.

The Rust target is always `riscv64gc-unknown-none-elf`. Direct `cargo` commands require the same env vars that `build.mk` sets (see `BUILD_ENV` there).

## Architecture Overview

KernelX is a `no_std` monolithic kernel. The top-level modules in `src/` are:

| Module | Role |
|--------|------|
| `arch` | Architecture abstraction — all arch-specific calls go through here |
| `kernel` | Core subsystems: mm, scheduler, task, syscall, ipc, event, usync |
| `fs` | VFS + concrete filesystems |
| `driver` | Device driver framework + concrete drivers |
| `klib` | Kernel utilities (allocator interface, SpinLock, InitedCell, logging macros) |

### Arch Layer (`src/arch/`)

`src/arch/mod.rs` uses `cfg_if` to select `riscv` or `loongarch` as the backend, then re-exports a uniform API via the `arch_export!` macro. The public types `UserContext`, `KernelContext`, `SigContext`, `PageTable` are type aliases to the concrete arch implementation. All callers use `crate::arch::*` — never the inner arch module directly.

### Boot Sequence

Arch-specific early boot (assembly + early mapping) → `kernel::main::main(hartid, heap_start, memory_top)`:
1. `kalloc::init` — kernel heap
2. `mm::init` — page frame allocator
3. `driver::init` / `arch::init` / `fs::init` / `arch::scan_device` — device tree probe + driver matching
4. `fs::mount_init_fs` — mount root filesystem from boot args
5. `task::create_initprocess` — spawn the first user process
6. `timer::init` / optional `spawn_kswapd` — timers and swap daemon
7. `arch::setup_all_cores` → `kentry` — enable interrupts and enter scheduler

### Memory Management (`src/kernel/mm/`)

- **Page allocator**: `mm::page` — physical page allocation/free
- **AddrSpace**: per-process address space holding a `MapArea` manager and a `PageTable`. Handles CoW, mmap, ELF loading, vDSO mapping, and (optionally) swap
- **MapArea types**: anonymous, file-backed private/shared, ELF segment, user stack/heap, shared memory
- **Swap**: `swap-memory` feature enables `kswapd` kernel thread with LRU eviction of anonymous pages

### Task/Scheduler (`src/kernel/task/`, `src/kernel/scheduler/`)

- `TCB` (thread control block) — per-thread: kernel stack, user/kernel contexts, signal state, time counters, FD table reference
- `PCB` (process control block) — per-process: address space, signal actions, working directory, child/parent links
- `Task` trait — implemented by user tasks and kernel threads; unified scheduler interface
- `Scheduler` — simple global FIFO ready queue; one `Processor` per hart
- `current` — per-CPU pointer to the running task's `Processor`

### Filesystem (`src/fs/`)

VFS layer: `Inode` + `Dentry` (with dentry cache) + `File` + `Superblock` abstractions in `src/fs/vfs/` and `src/fs/inode/`. Concrete filesystems: ext4 (via `lwext4_rust`), devfs, tmpfs, procfs, memfs/memtreefs, rootfs.

### Syscall Dispatch (`src/kernel/syscall/`)

`syscall::syscall(num, args)` dispatches by number (defined in `num.rs`) to category files: `fs.rs`, `mm.rs`, `task.rs`, `ipc.rs`, `event.rs`, `futex.rs`, `time.rs`, `misc.rs`, `uid.rs`. Returns `SysResult<usize>` (alias for `Result<usize, Errno>`). User pointer access goes through `uptr.rs` / `mm::ubuf`.

### Event System (`src/kernel/event/`)

Event-driven wakeup: `Event` bitmask, `WaitQueue`, `Poll` (for select/epoll), and `Timer`. Tasks block by storing an `Event` they wait on; the event fires → task is pushed back to the ready queue. Avoids polling for device I/O and timer waits.

### IPC (`src/kernel/ipc/`)

Pipe, POSIX signals (with sigaction, siginfo, pending queue), shared memory (shm), and futex (in `src/kernel/usync/`).

### Driver Framework (`src/driver/`)

Device discovery is FDT/device-tree driven (`driver/fdt.rs`). Drivers register compatible strings; `arch::scan_device` walks the tree and binds drivers. The `chosen` submodule provides system-wide singletons: default TTY (`kconsole`), RTC (`kclock`), power management (`kpmu`).
